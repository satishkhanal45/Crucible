## 3. What is left, in the order to do it

### Step 1 — Repair the seeded archive (blocker, do this first)

**The database does not contain the committed seed corpus.** `data/seeds/seed_attacks.yaml`
holds 40 seeds across 40 distinct cells; the archive holds **16 of them**:

```
round_generated = 0 → 16 attacks (3 holdout)   # should be 40 (8 holdout)
holdout ratio    → 5.1%                        # spec §10 requires 20%
```

The other 24 seeds were never admitted **and never rejected** — there is no
`novelty_rejections` row for any of them (all 12 rejections there carry
`round_number` 1 or 2, i.e. they came from loop rounds, not from seeding). The
only consistent explanation is that `crucible seed` was interrupted part-way
through `ArchiveService.admit_many` and its nine verification checks — one of
which asserts `archive_size >= 40` and another that the holdout ratio is within
0.05 of 0.20 — were never satisfied.

Everything measured so far inherits this. Run `9fed94ea`'s holdout block rate is
`n=3`, which is why its interval spans `[0.208, 0.939]`.

Fix:

```bash
make up && make migrate
make seed          # idempotent: seed ids are uuid5, already-present seeds are skipped
```

Then confirm **all nine checks pass**, and that `crucible archive stats` reports
40 round-0 attacks at roughly 20% holdout. Do not start an experiment until it
does. Note that re-seeding assigns holdout over the *newly admitted* batch, so
3 + ~5 of 24 ≈ 8 of 40 ≈ 20%, which is what the spec wants.

### Step 2 — Decide the archive baseline for the headline run

The archive currently also holds 43 attacks generated by the earlier, buggy
runs. `crucible experiment run` uses whatever is in the database; it does not
reset. So there are two defensible baselines and the choice belongs to the
operator:

- **Fresh archive (recommended).** Drop the database volume, migrate, seed, and
  run `main` from the committed 40 seeds. This is the only option under which
  the headline run is reproducible from the repository alone — the property
  content-addressed attack ids exist to provide, and the one `docs/findings.md`
  §1 claims under "Reproducibility".
- **Accumulate.** Keep the 43 existing attacks. The run starts from a richer
  archive, the block-rate curve mixes attacks from runs made under a broken
  defender prompt, and the seed no longer determines the archive.

If you choose fresh, note that the three `classifier_agreement` rows and the
three `experiment_results` rows are also in that database; export them first if
you want to keep the measured agreement figures (see 5.3).

### Step 3 — Pre-flight, before spending hours

```bash
uv run pytest -m live                       # the live benign-expectations test; minutes, cents
crucible experiment run main --smoke        # 1 round, live, 3 candidates, $0.50 cap
```

`--smoke` prints provider and model per agent, the round's rates with intervals,
and the cost. **A zero cost on a live run means the models are unpriced and the
budget is inert** — stop and fix the pricing table if you see one.

### Step 4 — Run the seven experiments

Suggested order, with the estimates `crucible experiment list` prints at
6500 TPM (the current `.env` gives DeepSeek 120000 TPM, so real times should be
much shorter):

| Order | Experiment | Rounds | ~minutes | Notes |
|---|---|---|---|---|
| 1 | `main` | 6 | 300 | the headline run; everything else is measured against it |
| 2 | `ablation_novelty` | 3 | 150 | `MIN_NOVELTY = 0` |
| 3 | `ablation_utility` | 3 | 150 | utility weight 0 — the most quotable result |
| 4 | `ablation_archive` | 3 | 150 | defender sees the current round only |
| 5 | `layer_ablation` | 1 | 120 | replay only; needs `main`'s final config |
| 6 | `transfer` | 1 | 40 | replays `main`'s archive against the clinic target |
| 7 | `model_overlap` | 1 | 30 | needs two model families to be reachable |

```bash
crucible experiment run main                # add --rounds N to shorten
crucible loop status                        # what is running, what halted
crucible loop resume --run-id <id>          # a checkpointed run continues mid-round
```

Steps 5–7 depend on `main` having finished, so run `main` first and let it
complete before starting the ablations.

A halted run is a valid result (spec §14) — write it up rather than re-running
it until it looks better.

### Step 5 — Regenerate every number

## 5. Facts and gotchas discovered while auditing (do not re-derive these)

### 5.1 DeepSeek pricing is now confirmed, and it was wrong before

`CLAUDE.md` carried a standing blocker: the DeepSeek rates in
`src/crucible/config.py` were placeholders and no cost figure derived from them
could reach `docs/findings.md`. They have now been checked against
<https://api-docs.deepseek.com/quick_start/pricing> (2026-09-06):

| Model | input, peak cache-miss | output, peak |
|---|---|---|
| `deepseek-v4-flash` | $0.44 / 1M | $1.32 / 1M |
| `deepseek-v4-pro` | $1.32 / 1M | $3.96 / 1M |
| `deepseek-v4-flash-vision-exp` | $0.44 / 1M | $1.32 / 1M |

DeepSeek publishes four input rates per model — cache hit and cache miss, each
peak and off-peak, where off-peak is half of peak and peak is 01:00–04:00 and
06:00–10:00 UTC on weekdays. The meter models neither caching nor time of day,
so the table records the **peak cache-miss** rate: the most expensive of the
four, which makes every recorded cost an upper bound rather than an
underestimate. Say so in findings when a cost figure appears there.

The old placeholders (`0.27` / `1.10`) understated the flash model by about 1.3×.
Recorded spend to date is $3.30 for ~2,000 live calls (2.48M prompt +
2.32M completion tokens on DeepSeek, plus 321 Groq calls); at the corrected
rates the same traffic is about $4.15.

**Budget for the remaining work: roughly $10–15** for all seven experiments,
against a `ROUND_BUDGET_USD` of 5.00 per run. The dominant cost is the
defender's proposal call, which spends 10,000–29,000 completion tokens of
reasoning to produce a ~1,500-character configuration (already written up as
limitation 3 in findings).

### 5.2 `findings regenerate` defaults to the *most recent* run

`FindingsData.gather()` with no `run_id` takes `runs.list_recent()[0]`. The most
recent row in this database is `c4f39bcf`, an orphaned `running` row with zero
rounds — so a bare `crucible findings regenerate` would publish an empty
headline while the real six-round run sat one row below it. **Always pass
`--run-id` when regenerating for publication.**

### 5.3 The classifier agreement is already measured and stored

`classifier_agreement` holds two rows, and they are the numbers `CLAUDE.md`
quotes:

| Model | objective | technique | combined |
|---|---|---|---|
| `openai/gpt-oss-120b` | 36/40 (90%) | 30/40 (75%) | 26/40 (65%) |
| `deepseek-v4-flash` | 38/40 (95%) | 32/40 (80%) | 30/40 (75%) |

Both axes are above the 0.70 line on the model the loop actually ran. This is
why `crucible findings regenerate --check` currently reports the
`taxonomy_agreement` block stale: the committed `docs/findings.md` holds the
empty-database rendering so CI passes on a fresh clone, and the local database
now has real data. That is expected, not a defect. **If you wipe the database
(step 2), re-run `crucible archive reclassify --dry-run` — it is 40 live
classifier calls — or these numbers are gone.**

### 5.4 All four agents currently run on DeepSeek

`.env` puts target, attacker, defender and classifier all on
`deepseek-v4-flash`. Findings limitation 2 is explicit that a run with all four
agents on one provider is *exactly* as vendor-dependent as a single-provider
build, and the run's recorded provenance is the authority. If you want to
weaken that limitation, move the attacker, defender or classifier to Groq
(`openai/gpt-oss-120b`) before the headline run. **The target cannot move**: the
`gpt-oss` family's structured-output path calls a built-in `json` tool that Groq
rejects, so a target on that family cannot complete a turn. That constraint is a
finding in its own right and belongs in the limitations.

### 5.5 What run `9fed94ea` actually showed, and why it is not the headline

Six rounds, halted on `utility_collapse` at utility 0.325 against a 0.34 floor.
Its block rate rose 0.583 → 0.643 while **D(n) stayed equal to D(0)** — the
defender produced zero valid configs for the whole run, because the prompt
documented only two of the four fields `HeuristicRule` requires. So the rising
curve is the archive accumulating attacks the target refuses unaided, not the
defense hardening. Both of those bugs are fixed (the prompt now carries the
whole generated schema; `utility_collapse` now requires a significant decline,
not just a low number; every rejected candidate logs its reason at WARNING). The
run is still in the database and is worth keeping as the "what a broken defender
looks like" example, but it is **not** a result to publish.

### 5.6 Before any long run

- `uv run pytest -m live` — the live variant of the benign-task test. A stub
  more permissive than reality has cost this project three separate incidents.
- Check <https://console.groq.com/docs/deprecations> if any agent is on Groq.
- `--smoke` first. Two minutes to learn that providers answer beats four hours
  to learn that they do not.
