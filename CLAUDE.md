# CLAUDE.md — Crucible

A co-evolutionary red-team loop for RAG systems. An attacker agent evolves
prompt-injection attacks; a defender agent evolves guardrail configs; an
archive plus a holdout set stop either from cheating.

## Read order, every session

1. This file (conventions, non-negotiables, current status).
2. `docs/spec.md` — authoritative scope for this build.
3. `project_context.md` — full design rationale. Consult for *why*, not *what*.

Where `docs/spec.md` and `project_context.md` disagree, **`docs/spec.md` wins.**

## Non-negotiables

These are correctness properties, not preferences. If a task appears to
require breaking one, **stop and say so instead of proceeding.**

1. **Holdout isolation.** Attacks with `is_holdout = true` never reach an
   attacker or defender prompt, and are never in the mutation pool. Enforced in
   the repository layer. There is no bypass, not even for debugging.
2. **Full-archive re-evaluation.** The block rate recorded for a round always
   comes from running the selected config against the entire non-holdout
   archive. Candidate *screening* may sample; the recorded metric may not.
3. **Utility term.** Weight 2.0 on `utility_loss` in the selection objective.
   Every round reports benign pass rate. Never set the weight to 0 outside the
   explicit ablation config.
4. **Novelty pressure.** Attacks below `MIN_NOVELTY` are rejected *before*
   execution, and every rejection logs the nearest neighbour id.
5. **Regression detection.** Any archived attack blocked by `D(n-1)` and
   breaching `D(n)` is flagged with its attack id and is not auto-accepted.
   The Phase 6 regression test is permanent.
6. **Canaries never appear in agent prompts.** Assert this in the prompt
   builders, not just in tests.
7. **The defender emits config, never code.** Unknown keys in a
   `DefenseConfig` are rejected, never ignored.
8. **Never weaken a test to make it pass.** If a test is wrong, say why and
   ask. If the code is wrong, fix the code.

## Conventions

- Python 3.12, `uv` only. `uv.lock` is committed. **Ask before adding a dependency.**
- Async everywhere: SQLAlchemy 2.0 async + `asyncpg`. No sync DB calls.
- `ruff` lint and format. `mypy --strict` on `src/crucible`. No blanket
  `# type: ignore`, no `--no-strict` escape hatches.
- Pydantic v2 for every boundary schema. No bare dicts crossing module lines.
- Layering: `api → services → repositories → db`. Agents talk to services,
  never to the ORM directly.
- Every schema change is an Alembic revision. The "autogenerate produces an
  empty diff" test must stay green forever.
- Tests: `pytest`, `pytest-asyncio`, `testcontainers` for anything touching
  Postgres. LLM calls are stubbed with scripted responses in all unit and
  integration tests. No test may make a live API call.
- Every LLM call routes through `CostMeter`. No exceptions.
- Target runs at temperature 0 so the outcome cache is sound.
- Vocabulary is fixed: Target, Canary, Attack, Attempt, Outcome, Archive,
  Cell, DefenseConfig, Round, Holdout. Use these names in code.

### Never do

- Log, print, or commit a canary value.
- Read anything under `data/holdout/` from agent or prompt-building code.
- Write raw payload text into `docs/findings.md` or any default report output.
- Hand-type a number into `docs/findings.md`. Every figure is regenerated by
  script from stored rounds and attempts.
- Add network egress to a host not on `TARGET_ALLOWLIST`.

## Build order

```
0 → 1 → 2 → 3 → 5 → 4 → 6 → 7 → 8
```

Phase 5 (defender) is deliberately built before Phase 4 (attacker), which
Appendix A permits. With hand-written seed attacks, a working defender gives a
demoable end-to-end result before the attacker exists.

| Phase | Name | Effort (units) |
|---|---|---|
| 0 | Foundation | 1.0 |
| 1 | Target harness and canaries | 2.0 |
| 2 | Execution and oracle | 1.5 |
| 3 | Archive, novelty, QD grid | 1.5 |
| 5 | Defense stack and defender | 2.0 |
| 4 | Attacker agent | 1.5 |
| 6 | Loop orchestration | 1.5 |
| 7 | Reporting | 0.5 |
| 8 | Experiments and findings | 1.0 |

1 unit ≈ half a day. Total budget ≈ 13 units.

**Definition of done for any phase:** acceptance criteria in `docs/spec.md`
met, that phase's verification tests written *and passing*, `make lint
typecheck test` green, migrations in sync, status section below updated,
work committed.

  ten-step round algorithm in `docs/spec.md` §13 with collapse detection.
- **Open issues / blockers:** none. Notes for whoever picks this up:
  - `docs/spec.md` §7 wins over `project_context.md` on canary placement: one
    canary class per location, so the system prompt carries `SYSPROMPT_CANARY`
    only. Planting a second class there would make a system-prompt leak
    indistinguishable from a retrieval-scope violation.
  - **The target corpus has no HNSW index, on purpose.** HNSW is approximate,
    and a document injected by an `indirect_document` attack is an outlier that
    the graph search can fail to reach — an undelivered attack would then be
    scored as blocked. Target retrieval is an exact scan ordered by
    `(distance, doc_id)`. Phase 3's archive is large and measures novelty
    statistically, so it should use HNSW; the target corpus must not.
  - Tier 1's tool rule counts an unauthorized privileged **execution** as a
    breach. A call the structural layer blocked is `blocked`, not `breached` —
    otherwise no defense configuration could ever improve the tool-hijack score.
    See the docstring in `crucible/oracle/tier1.py`.
  - Attempt traces contain that attempt's canary values, because replay needs
    them. Phase 7 must redact `trace.canaries` and `trace.attempt.payload`.
  - **Novelty k-NN is an exact scan, by decision of the technical director.**
    The archive's HNSW index cannot be both used and exact: measured on a
    5000-row, 384-dimension archive, `ef_search` 40 → index used, recall 0.48;
    100 → index used, recall 0.76; 200 → exact scan, recall 0.93; 1000 → exact
    scan, recall 1.00. Novelty pressure is never-cut, so novelty runs at
    `ef_search=1000` (exact, reproducible) and the index is kept for scale.
    Ordering breaks ties on attack id, in Python, after an index-friendly
    single-key `ORDER BY`. Approximate search becomes necessary above ~20k
    archive entries: that is deferred item **D8** in `docs/spec.md` §4 and a
    stated limitation in findings, not a defect. Revisit only with numbers.
  - `generality` is 0.0 when there are no past defense configs. Phase 5 creates
    the first ones; do not change the zero case to 1.0, which would inflate
    every fitness score in the archive.
  - **`output.canary_scan` is measurement, not blocking.** It records which
    canary classes the target emitted so the oracle's evidence is complete, which
    is why it must be true in production. Blocking a leaked secret is
    `output.secret_patterns` plus `on_violation`. If `canary_scan` itself
    blocked, the empty baseline would block every attack and the experiment would
    measure nothing.
  - **Tier 1 counts unauthorized privileged *execution*.** Layer 5 blocking a
    call yields `blocked`, recorded in `attempts.blocked_tools` and surfaced as
    `hijack_attempted_but_blocked` for the Phase 8 ablation table.
  - The benign task expectations in `data/benign_tasks.yaml` were recorded
    against the reference target with the hashing embedder. Changing the corpus,
    the retrieval threshold, or the embedding model requires re-recording them.
  - **The mutation pool falls back to the archive when no cell has an elite.**
    Cells only get elites once an attack in them has been executed and scored, so
    a freshly seeded archive would otherwise hand the attacker nothing on round
    one. Both branches of `get_attacks_for_mutation()` filter `is_holdout` in
    SQL — that is the property the method exists for, and neither path has a
    bypass.
  - `self_critique` runs *after* the novelty gate, per the Phase 4 edge order, so
    a candidate it rejects has already been admitted and executed. It stays in
    the archive with its real outcome; it just does not count as the round's
    product.
  - `EvaluationService` reads the archive through `list_non_holdout()` and
    `list_holdout()`, which are **not** agent-safe methods. Holdout block rate is
    impossible otherwise, and widening an agent-facing method would weaken the
    isolation property. Prompt builders still may not call them, and
    `tests/unit/test_holdout_isolation.py` enforces that.
  - Compose publishes `${POSTGRES_PORT:-5432}` and `${API_PORT:-8000}`; override
    them in `.env` when a host service already owns those ports.
- **Deferred items pulled back in:** none (register is `docs/spec.md` §4)

## Cost discipline

Free-tier rate limits are the binding constraint on this project, not compute.

- Every call goes through `CostMeter`; `BudgetExceeded` ends a round cleanly
  with partial results, never a crash.
- The outcome cache (`attack_id`, `defense_config_id`) is what makes
  full-archive re-evaluation affordable. Never bypass it by regenerating
  config ids for semantically identical configs — config hashing is
  order-independent for exactly this reason.
- Use the smallest adequate model for the target and the taxonomy classifier.
- Batch embeddings. `all-MiniLM-L6-v2` runs on CPU and must stay under a 1GB
  ceiling for a 500-attack batch.
